# GenAnT post-flight checks

Before using the anntotations generated by GenAnt, I reccomend looking at a few of the intermediate files. This is because there are a lot of options of different input files (i.e., number of reference species, RNA-seq data, etc.) there may be instances where an individual annotation tool fails but the rest of pipeline continues.

# 1. Were all of the correct GFF files included

Step 2 involves generating a series of individual GFF files from different tools (e.g., braker, stringtie, TOGA, liftoff) depending on the available inputted data (e.g., reference genomes, RNA-seq/ISO-seq data). Our automated pipleine makes an empty GFF file that is later ignored if GenAnT does not think that you have the necessary input data to perform the annotation task (e.g., no ISO-seq data therefore Braker-long read is ignored).

### Were the excluded GFF files intentional

```
# Check to see which files were excludeds
ls $outDir/transcript_selection/excluded_input
```

For example I had a run where I only used one reference species for TOGA and I had both RNA-seq and ISO-seq data, so the directory looked like this:
```
braker.noRNA.gffread.gff  custom.gffread.gff  toga.r2.gffread.gff
```

If your excluded GFF files make sense given the input data that you have then excellent. If not, please go to "Empty gff files" of the `clean_GenAnT_after_failure.md` to ensure that the pipeline runs properly after you sucessfully rerun whichever element of "Step 2" outright failed.

### Do the included GFF files look reasonable

While we have never experienced an issue with a sucessfully generated gff file having an issue, it's probably worth it to take a cursory look. at each of the gff files in transcript selection.

Below is an `awk` liner that will print out the number of "gene" features assigned to each chromosome for each gff file in your assembly. If for example, all of the GFF files annotate ~1100-1300 genes to chromosome 1, and one GFF file annotations 100 genes to chromosome 1. That GFF file may be worth inspection.

```
for i in $outDir/transcript_selection/*.gff ; do echo $i ; awk -F'\t' '$3 == "gene" {counts[$1]++} END {for (chr in counts) print chr "\t" counts[chr]}' $i | sort ; done
```

### Were non-coding RNA sucessfully annotated?

You can also look the "type" of features being annotated in the final GFF file to make sure that coding and non-coding regions were annotated. It may be helpful to load the gff file into R with `rtracklayer()` or into python to just look at your GFF file. Alternatively here is an awk liner to print out the number of elements in each "type" below

```
awk -F'\t' '!/^#/ {count[$3]++} END {for (feature in count) print feature "\t" count[feature]}' $outDir/full_annotation.geneSymbols.gff | sort
```

### Annotated gene structure

Lastly, mikado outputs a very useful and comprehensive table with the `metrics.tsv` suffix. This can be found in `$outDir/transcript_selection/"mikado_lenient.metrics.tsv"`. All of the metrics can be found below. One table I like to make is the comparison of the original "source" and the "is_complete" scores.
"Source" tells you which tool from step 2 had the "best looking" and therefore "selected" transcript as the base to build the gene model on. "is_complete" states whether the gene has a clear start codon, stop codon, and open reading frame.

Below is an example of using GenAnT to upgrade an existing assembly (transcripts lifted over from the same species with LiftOff) using new RNA-seq and ISO-seq data. As such most transcript models are from LiftOff (the existing assembly) or Stringtie, which is reliant on sthe new RNA-seq and ISO-seq data. 
```
 table(metrics$original_source,metrics$is_complete)
            False  True
  braker.lr     1  5546
  braker.sr     1  4694
  liftoff    1487 22987
  stringtie 11133 15218
  toga.r1     199  2936
```

StringTie also called many transcripts without a clear start- and stop- codon. We can see that it also calls many ncRNA transcripts (ORF < 100) by investigating these tables.

```
table(metrics$original_source,metrics$combined_cds_length > 100)
            FALSE  TRUE
  braker.lr     0  5547
  braker.sr     0  4695
  liftoff      23 24451
  stringtie  7599 18752
  toga.r1       0  3135
```
